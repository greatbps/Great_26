1. `claude.md`의 본질과 작동 원리

- **컨텍스트 엔지니어링의 핵심:** AI에게 꼭 필요한 정보만 정확하게 전달하는 기술의 출발점이며, 클로드 코드에서 가장 높은 레버리지(지렛대) 효과를 내는 파일이다.
- **사전 지시서 역할:** 클로드 코드를 실행하면 가장 먼저 `claude.md`를 찾아 통째로 읽는다. 이 파일은 시스템 프롬프트 바로 다음, 사용자의 입력보다 먼저 읽히는 '사전 지시서' 역할을 한다.
- **⚠️ 주의 - 맥락이지 강제가 아니다:** 공식 문서에 따르면 이 파일은 강제성을 띠는 시스템 프롬프트가 아니라 사용자 메시지로 전달된다. 따라서 지시가 모호하거나 충돌하면 클로드가 규칙을 무시할 수 있으므로, **어떻게 구체적으로 쓰느냐**가 가장 중요하다.

2. 오토 메모리 (Auto Memory) 활용법

- `claude.md`가 사용자가 주는 업무 매뉴얼이라면, **오토 메모리는 클로드가 스스로 적는 업무 일지**다.
- 세션 중 사용자의 선호도나 프로젝트 특징을 알아서 기록하며, `/memory` 명령어로 언제든 확인하고 직접 수정/삭제할 수 있다.
- 메모리는 처음 200만 토큰에 로드되며, 파일이 200줄이 넘어가면 클로드가 알아서 별도의 주제 파일로 분리하여 필요할 때만 찾아 읽는다.

3. 절대 피해야 할 '나쁜 패턴' 3가지

4. **너무 긴 파일 (300줄 이상):** 공식 문서에서는 200줄 이하 작성을 권장한다. 너무 길어지면 중요한 규칙이 노이즈에 묻혀 무시당하므로 과감히 삭제하거나 정리해야 한다.
5. **모호한 지시:** "깔끔한 코드를 작성하세요" 같은 모호한 말은 통하지 않는다. 대신 "함수는 30자 이하로 작성하세요", "새 파일을 만들기 전에 나한테 확인하세요"처럼 **클로드 스스로가 지켰는지 검증 가능한 구체적인 지시**를 내려야 한다.
6. **단일 파일 고집:** 프로젝트가 커졌는데도 루트 디렉터리의 `claude.md` 하나만 쓰면 아키텍처 규칙을 어기기 시작한다. 모듈식으로 분리해야 한다.

7. 실전 적용! '좋은 패턴' 4가지 (🔥 핵심)

8. **스스로 검증할 방법 제공 (최고의 레버리지):** 클로드에게 작업 결과를 스스로 검증할 수 있는 규칙(예: 빌드/테스트 명령어)을 적어두면, 에러가 나도 스스로 고치는 자동 루프가 돌아가 품질이 2~3배 향상된다.
9. **비즈니스 도메인 용어 정의:** 비즈니스에서 쓰는 고유 용어(예: 배달 앱에서 결제 묶음인 '주문'과 개별 음식인 '주문 항목')를 정의해 두면 클로드가 엉뚱한 코드를 짜는 헷갈림을 완벽히 방지할 수 있다.
10. **모듈식 관리와 임포트(****@****):** 규칙이 길어지면 하위 디렉터리별로 마크다운 파일을 나눠서 관리한다. `claude.md`에 `@` 기호를 사용해 기존 문서를 참조(Import)하면 중복 작성 없이 필요할 때만 로드하게 할 수 있다.
11. **공유 학습 시스템으로 사용하기:** **처음부터 완벽하게 쓰려고 하지 마라.** 빈 파일에서 시작하되, 클로드가 실수할 때마다 "다음부턴 이렇게 해"라며 **한 줄씩 규칙을 추가**해 나가는 것이 핵심이다. 가끔 클로드에게 "우리 `claude.md` 파일 리뷰해서 빠진 게 있는지 확인해 줘"라고 시켜 유지보수하는 것도 꿀팁이다.
