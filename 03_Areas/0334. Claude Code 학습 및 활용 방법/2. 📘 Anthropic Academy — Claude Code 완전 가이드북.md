# 📗 섹션 1 — What is Claude Code?

## 1-1. Introduction

이 코스는 Claude Code를 실제 업무에 활용하는 방법을 가르치는 **실습 중심** 코스입니다.

배우게 될 것들:

- Claude Code의 작동 원리
- 컨텍스트(Context) 추가 방법
- 커스텀 명령어(Custom Commands) 만들기
- MCP 서버(MCP Servers) 연동
- GitHub 통합
- Hooks 시스템 이해 및 구현
- Claude Code SDK 활용

---

## 1-2. What is a Coding Assistant?

### 두 가지 유형의 코딩 어시스턴트

|유형|대표 예시|특징|
|---|---|---|
|자동완성 도구|GitHub Copilot|타이핑 중 실시간 코드 제안. 에디터 내부에서 동작|
|**에이전트형 도구**|**Claude Code**|자율적으로 작업 완료. 파일 읽기·편집·명령 실행까지|

### Tool Use — Claude Code가 다른 이유

> [!note] 핵심 개념

> 언어 모델 자체는 파일을 읽거나 명령을 실행할 수 없습니다. Claude Code는 **Tool Use** 시스템을 통해 이 한계를 극복합니다.

**전체 흐름:**

1. 사용자가 요청 입력
2. Claude Code가 도구 지시사항을 자동으로 추가
3. 모델이 `ReadFile: main.go` 식으로 응답
4. Claude Code가 실제 파일을 읽고 결과를 모델에 전달
5. 모델이 최종 답변 제공

**기본 내장 도구 전체 목록:**

|도구|용도|
|---|---|
|`Agent`|서브에이전트를 실행해 작업 처리|
|`Bash`|셸 명령어 실행|
|`Edit / MultiEdit`|파일 편집 (단일 / 다중 동시)|
|`Glob`|패턴으로 파일 찾기|
|`Grep`|파일 내용 검색|
|`LS`|디렉토리 목록 보기|
|`Read / Write`|파일 읽기 / 쓰기|
|`NotebookRead / NotebookEdit`|Jupyter 노트북 셀 읽기 / 편집|
|`TodoRead / TodoWrite`|할 일 목록 관리|
|`WebFetch / WebSearch`|URL 데이터 가져오기 / 웹 검색|

## 1-3. Claude Code in Action — 실전 데모 4가지

- 🔬 데모 1 — chalk 라이브러리 성능 최적화
    
    JavaScript 생태계 주간 다운로드 **4억 2,900만 건** 패키지의 성능 개선 프로젝트.
    
    - 벤치마크 실행 → 병목 구간 식별 → CPU 프로파일러 분석 → 코드 수정
    - **결과: 처리량 3.9배 향상**
    
    사용 도구: `TodoWrite` (진행 추적), `Bash` (벤치마크 실행), `Write` (분석 파일 작성)
    
- 📊 데모 2 — Jupyter 노트북 데이터 분석
    
    비디오 스트리밍 플랫폼 사용자 이탈 원인 분석.
    
    - 단순히 코드를 작성하는 것을 넘어 **셀을 직접 실행하고 결과를 확인하며** 이후 셀을 맞춤화
    - 이것이 Tool Use 기반 에이전트의 핵심 강점
- 🎨 데모 3 — Playwright MCP + UI 스타일링
    
    Claude Code에 Playwright MCP 서버를 추가하여 **브라우저를 직접 열고**, 실제 렌더링 화면을 보면서 스타일링 개선.
    
    - 코드만 보는 것이 아닌 **실제 시각적 출력을 보고 판단**
    - 일반 보라-파란 그라디언트 → 훨씬 창의적인 디자인으로 이터레이션
- 🔐 데모 4 — GitHub Actions PR 자동 보안 리뷰
    
    AWS 인프라가 Terraform으로 관리되는 시나리오.
    
    - 이메일 필드를 S3 버킷에 추가하는 코드 한 줄이 외부 파트너에게 **PII(개인식별정보)를 노출**시킬 수 있다는 문제를 Claude Code가 PR 리뷰에서 **자동으로 감지·보고**

## 2-3. Adding Context

> [!note] 핵심 원칙

> 관련 없는 컨텍스트가 많을수록 Claude의 효율성이 감소합니다. **필요한 정보만 정확하게** 제공하세요.

### /init — 프로젝트 첫 시작 시 필수

새 프로젝트에서 `/init` 실행 → Claude가 전체 코드베이스를 분석 → **`CLAUDE.md`** 자동 생성

```
/init
```

- **Enter** — 파일 작성 개별 승인
- **Shift+Tab** — 세션 전체에서 자유롭게 파일 쓰기 허용

### [CLAUDE.md](http://CLAUDE.md) — AI한테 주는 업무 매뉴얼

|파일 위치|범위|용도|
|---|---|---|
|`.claude/CLAUDE.md`|해당 프로젝트|프로젝트 구조, 핵심 파일. Git 커밋하여 팀 공유|
|`.claude/CLAUDE.local.md`|해당 프로젝트, 본인만|개인 지침. Git 커밋 안 함|
|`~/.claude/CLAUDE.md`|모든 프로젝트|기기 전체에 적용되는 글로벌 지침|

```markdown
## 프로젝트 개요
Meta, Google 광고 데이터를 분석합니다.

## 주요 파일
- data/ : 원본 CSV 데이터
- reports/ : 분석 결과물

## 규칙
- 보고서는 항상 숫자 먼저, 해석 나중에
- 주석은 꼭 필요한 경우에만
```

### # 단축키 — 대화 중 [CLAUDE.md](http://CLAUDE.md)에 즉시 추가

```
# 보고서 작성할 때 반드시 표 형식으로 정리해줘
→ project CLAUDE.md 선택 → 자동 추가
```

### @ 파일 참조 — 특정 파일을 컨텍스트에 즉시 포함

```
@schema.prisma 파일 기준으로 사용자 테이블 구조 설명해줘
```

[CLAUDE.md](http://CLAUDE.md) 안에 `@` 참조를 추가하면 매 요청마다 자동 포함됩니다.

## 2-4. Making Changes

### 스크린샷 붙여넣기

> [!warning] ⚠️ Mac에서도 Ctrl+V입니다 (Cmd+V ❌)

> 화면 캡처 후 Claude Code 창에서 **Ctrl+V** → "이 부분 바꿔줘" 입력

### Planning Mode — 큰 작업 전에 계획 먼저

**Shift+Tab 두 번** (자동 수락 모드에서는 한 번)

- 프로젝트 내 더 많은 파일 읽기
- 상세한 구현 계획 수립 → 사용자에게 미리 보여줌
- 사용자 승인 후 구현 진행

여러 파일에 걸친 변경, 코드베이스 전반 이해가 필요한 작업에 적합합니다.

### Thinking Mode — 복잡한 판단은 더 깊게

|구문|추론 수준|
|---|---|
|`think`|기본 추론|
|`think more`|확장 추론|
|`think a lot`|포괄적 추론|
|`think longer`|장시간 추론|
|`ultrathink`|최대 추론|

```
지난달 대비 ROAS 30% 하락 원인을 ultrathink로 분석해줘
```

### Planning vs Thinking — 언제 무엇을?

||Planning Mode|Thinking Mode|
|---|---|---|
|적합한 상황|코드베이스 전반, 여러 파일에 걸친 변경|복잡한 로직, 어려운 버그, 알고리즘|
|방식|광범위 탐색 (Breadth-first)|심층 추론 (Depth-first)|

두 모드를 **함께 사용**하면 넓이와 깊이가 모두 필요한 작업에 효과적입니다 (단, 토큰 비용 증가).

## 2-5. Controlling Context

### 핵심 단축키 4가지

|단축키|언제 쓰나|
|---|---|
|`Escape`|Claude가 잘못된 방향으로 갈 때 즉시 중단|
|`Escape` • `#`|같은 실수 반복 시. 올바른 방법을 [CLAUDE.md](http://CLAUDE.md)에 영구 기록|
|`Escape` 두 번|불필요한 중간 대화 제거. 특정 시점으로 되감기|
|`/compact`|관련 후속 작업 시. 핵심 지식 유지하며 대화 압축|
|`/clear`|완전히 다른 새 작업 시작 시|

- 📖 Escape 두 번 활용 예시
    1. `createSession` 테스트 작성 요청
    2. Claude가 깨진 패키지 문제로 디버깅에 시간 낭비
    3. 테스트는 완성됐지만 불필요한 디버깅 대화가 남음
    4. 다음 작업 `getSession` 시작 전 → **Escape 두 번**
    5. "createSession 테스트 작성해줘" 시점으로 되감기
    6. 코드베이스 이해(컨텍스트)는 유지 + 불필요한 디버깅 기록 제거 ✅

## 2-6. Custom Commands

파일 하나 만들면 `/명령어`가 생깁니다.

```
.claude/
└── commands/
    ├── weekly.md      →  /weekly 명령어
    └── analyze.md     →  /analyze 명령어
```

> [!warning] 파일 생성 후 Claude Code 재시작 필요

### 예시 1 — /weekly (매주 광고 리포트)

```markdown
매주 월요일 광고 성과 리포트를 작성합니다.

1. data/weekly/ 폴더에서 이번 주 파일을 찾아요
2. Meta, Google, Kakao 채널별로 정리해요
3. ROAS, 지출, 전환수를 계산해요
4. 지난주 대비 증감률을 계산해요
5. 주요 이슈가 있으면 3줄로 요약해요
6. reports/weekly_YYYY-MM-DD.md로 저장해요
```

### 예시 2 — /analyze (인자 전달)

```markdown
다음 파일을 분석해서 인사이트를 뽑아주세요: $ARGUMENTS
```

```bash
/analyze meta_june.csv
/analyze google_q2_report.xlsx
```

`$ARGUMENTS`는 파일 경로 외에 어떤 문자열이든 전달 가능합니다.

## 2-7. MCP Servers with Claude Code

> [!note] MCP란?

> Claude Code에 새로운 능력을 추가하는 **플러그인 시스템**입니다. 스마트폰에 앱을 설치하면 새 기능이 생기는 것과 같은 원리입니다.

### Playwright MCP — 브라우저 직접 제어

```bash
# 터미널에서 실행 (Claude Code 외부)
claude mcp add playwright npx @playwright/mcp@latest
```

이걸 설치하면 가능해지는 것:

```
우리 쇼핑몰 상품 페이지 들어가서
메인 이미지 크기가 적절한지 확인하고
개선 포인트 알려줘
```

Claude가 **실제로 브라우저를 열고, 화면을 보면서** 분석합니다.

### 권한 사전 승인 설정

`.claude/settings.local.json`에 추가:

```json
{
  "permissions": {
    "allow": ["mcp__playwright"],
    "deny": []
  }
}
```

> [!warning] `mcp__playwright` — 밑줄 두 개(`__`)입니다

### 워크플로우 커스터마이징

```yaml
# 1. 프로젝트 사전 설정
- name: Project Setup
  run: |
    npm run setup
    npm run dev:daemon

# 2. Claude에게 컨텍스트 제공
custom_instructions: |
  The project is already set up.
  The server is running at localhost:3000.

# 3. MCP 서버 구성
mcp_config: |
  {"mcpServers": {"playwright": {"command": "npx", "args": ["@playwright/mcp@latest"]}}}
```

> [!warning] GitHub Actions에서의 권한 관리

> 로컬의 Shift+Tab과 달리, GitHub Actions에서는 MCP 서버의 각 도구를 `allowed_tools`에 **개별적으로** 명시해야 합니다.

# 📗 섹션 3 — Hooks and the SDK

## 3-1. Introducing Hooks

Hook은 Claude가 도구를 실행하기 **직전(PreToolUse)** 또는 **직후(PostToolUse)**에 커스텀 명령어를 실행하는 기능입니다.

```
일반: 사용자 → Claude → 도구 실행 → 결과

Hook: 사용자 → Claude → [Pre Hook] → 도구 실행 → [Post Hook] → 결과
```

|유형|차단 가능|주요 용도|
|---|---|---|
|`PreToolUse`|✅ 가능|민감 파일 접근 차단, 위험 명령 차단|
|`PostToolUse`|❌ 불가|타입 체크, 테스트 실행, 중복 감지|

### 훅 설정 위치

|위치|파일|범위|
|---|---|---|
|글로벌|`~/.claude/settings.json`|모든 프로젝트|
|프로젝트 공유|`.claude/settings.json`|팀 공유|
|프로젝트 개인|`.claude/settings.local.json`|본인 전용|

## 3-2. Defining Hooks

### 훅 생성 4단계

1. **PreToolUse vs PostToolUse 결정** — 차단이 필요하면 Pre, 후속 작업이 필요하면 Post
2. **감시할 도구 결정** — `|`로 OR 연산 (예: `Read|Grep`)
3. **커맨드 작성** — stdin으로 JSON을 받아 처리하는 스크립트
4. **종료 코드로 제어** — Exit 0: 허용 / Exit 2: 차단 (PreToolUse 전용)

### 훅 스크립트가 받는 JSON

```json
{
  "session_id": "2d6a1e4d-6...",
  "hook_event_name": "PreToolUse",
  "tool_name": "Read",
  "tool_input": {
    "file_path": "/code/queries/.env"
  }
}
```

### 종료 코드

|Exit Code|의미|비고|
|---|---|---|
|`0`|허용|도구 호출 진행|
|`2`|차단|PreToolUse 전용. stderr 메시지가 Claude에 피드백으로 전달|

## 3-3. Implementing a Hook

**.env 파일 접근 차단** PreToolUse 훅 구현 예시

### settings.local.json 설정

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Read|Grep",
      "hooks": [{
        "type": "command",
        "command": "node /절대경로/hooks/read_hook.js"
      }]
    }]
  }
}
```

### read_hook.js 핵심 로직

```jsx
let inputData = '';
process.stdin.on('data', (chunk) => { inputData += chunk; });
process.stdin.on('end', () => {
  const data = JSON.parse(inputData);
  const toolInput = data.tool_input;

  // Read는 file_path, Grep은 path 필드 사용
  const filePath = toolInput.file_path || toolInput.path || '';

  if (filePath.endsWith('.env') || filePath.includes('/.env')) {
    console.error('You cannot read the .env file.');
    process.exit(2);  // 차단
  }
  process.exit(0);  // 허용
});
```

> [!warning] 훅 변경 후 반드시 Claude Code 재시작

## 3-4. Gotchas Around Hooks

### 절대 경로 사용 권장 (보안)

공식 문서는 **경로 인터셉션(path interception)** 및 **바이너리 플랜팅(binary planting)** 공격 방지를 위해 절대 경로 사용을 권장합니다.

**문제:** 절대 경로는 개발자마다 달라 팀 공유가 어렵습니다.

### 해결책 — $PWD 플레이스홀더 패턴

```json
// settings.example.json (저장소에 포함)
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Read|Grep",
      "hooks": [{
        "type": "command",
        "command": "node $PWD/hooks/read_hook.js"
      }]
    }]
  }
}
```

`npm run setup` 실행 시 `init-claude.js`가 `$PWD`를 실제 절대 경로로 교체 → `settings.local.json`으로 자동 저장

**결과:** 보안 유지 + 팀 공유 가능 ✅

## 3-5. Useful Hooks!

### Hook 1 — TypeScript 타입 체커 (PostToolUse)

**문제:** Claude가 함수 시그니처를 변경하면 다른 파일의 타입 에러를 놓칩니다.

**해결:** 파일 편집 시마다 `tsc --noEmit` 자동 실행 → 에러 발견 시 Claude에 즉시 피드백

```json
{
  "PostToolUse": [{
    "matcher": "Edit|Write|MultiEdit",
    "hooks": [{
      "type": "command",
      "command": "node /절대경로/hooks/typecheck_hook.js"
    }]
  }]
}
```

> [!tip] 타입 언어가 아닌 경우에도 동일한 원리로 **자동화 테스트를 피드백**하는 훅으로 구현 가능

---

### Hook 2 — 쿼리 중복 감지 (PostToolUse + SDK)

**문제:** `/compact` 후 Claude가 기존 쿼리를 잊고 중복 코드를 작성합니다.

**해결:** `queries/` 디렉터리 편집 시 **SDK로 별도 Claude 인스턴스**를 실행하여 중복 여부 검토

```
파일 편집 감지
→ SDK로 두 번째 Claude 인스턴스 실행
→ "이미 같은 기능의 쿼리가 있는지 확인해줘"
→ 중복 발견 시 원래 Claude에 피드백
→ 원래 Claude가 중복 제거 & 기존 함수 사용
```

|장점|단점|
|---|---|
|중복 코드 자동 방지|편집마다 추가 시간 + API 비용|
|코드베이스 품질 향상|범위 넓을수록 오버헤드 증가|

> [!tip] 핵심 비즈니스 로직 폴더 몇 개만 선택적으로 감시하여 오버헤드를 최소화하세요.

## 3-6. Another Useful Hook — 추가 훅 유형

|훅 유형|실행 시점|
|---|---|
|`Notification`|Claude Code가 알림을 전송할 때 (권한 요청 시, 60초 유휴 후)|
|`Stop`|Claude Code 응답 완료 시|
|`SubagentStop`|서브에이전트("Task")가 완료되었을 때|
|`PreCompact`|compact 작업(수동/자동) 실행 직전|
|`UserPromptSubmit`|사용자가 프롬프트를 제출했을 때 (Claude 처리 전)|
|`SessionStart`|세션 시작 또는 재개 시|
|`SessionEnd`|세션 종료 시|

### 꿀팁 — stdin 구조 파악용 로깅 훅

훅 유형마다 stdin JSON 구조가 다릅니다. 먼저 이 디버깅 훅으로 확인하세요:

```json
{
  "PostToolUse": [{
    "matcher": "*",
    "hooks": [{
      "type": "command",
      "command": "jq . > post-log.json"
    }]
  }]
}
```

`post-log.json`을 열어 실제 JSON 구조 확인 후 본격적인 훅 구현을 시작하세요.

## 3-7. The Claude Code SDK

Claude Code를 **프로그래매틱하게** 제어하는 도구입니다.

### 지원 환경

- TypeScript: `@anthropic-ai/claude-code` 패키지
- Python 라이브러리
- CLI

### TypeScript 기본 사용법

```tsx
import { query } from '@anthropic-ai/claude-code';

// 기본 사용 (읽기 전용)
const result = await query({
  prompt: '프로젝트의 main.ts 파일을 읽고 요약해달라'
});

// 쓰기 권한 포함
const result = await query({
  prompt: '...',
  options: { allowTools: ['Edit', 'Write', 'Read'] }
});
```

> [!warning] SDK 기본 권한은 읽기 전용

> `Read`, `Grep`, `Glob` 등은 가능하지만 `Write`, `Edit`은 `allowTools` 옵션으로 명시해야 합니다.

### SDK 활용 방향

- **훅 내부에서** — 특정 이벤트 발생 시 Claude Code를 자동 실행 (3-5 쿼리 중복 감지 훅에서 이미 활용)
- **커스텀 커맨드** — `/` 명령어에서 SDK를 호출하는 복잡한 자동화
- **자동화 스크립트** — 반복적인 작업을 자동화하는 파이프라인에 통합
