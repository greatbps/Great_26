## 메모
### 🔑 핵심 요약

- **(00:00)**  
    새로운 AI 플러그인이 계속 나오면서 “안 쓰면 뒤처진다”는 분위기가 있지만,  
    오히려 도구 학습에 시간 쓰느라 **실제 생산성이 떨어지는 문제**가 발생함.
- **(00:37)**  
    소개 플러그인 2가지
    1. Codex 플러그인 (OpenAI)
    2. Superpowers (깃허브 스타 ~10만, 2026년 급성장 프로젝트)
- **(01:09)**  
    플러그인 탐색 방법
    - 공식 디렉토리 + GitHub curated 리스트 활용
    - 트렌딩보다 “Claude Code 전용 큐레이션”이 더 효율적
- **(01:43)**  
    Codex 플러그인의 핵심 목적  
    → Claude Code의 **코드 리뷰 한계 해결 (자기 코드 자기 검증 문제)**
- **(02:21)**  
    Claude vs Codex 특징
    - Claude: 기획/창의성 강점, 대신 오버엔지니어링/컨텍스트 문제
    - Codex: 리뷰/분석 강점, 대신 창의성 부족  
        → **상호 보완 구조**
- **(02:56)**  
    Codex 주요 기능
    - 코드 리뷰 (읽기 전용)
    - 공격적(adversarial) 테스트
    - 작업 위임(코드 수정 가능)  
        → **토큰 절약 + 리뷰 품질 개선**
- **(03:36)**  
    Codex 단점
    - 두 모델 비용/사용량 관리 필요
    - 직접 API 호출 대비 제어력 낮음 (대신 편의성 ↑)
- **(04:15)**  
    Superpowers 핵심  
    → Claude Code에 **TDD(테스트 주도 개발) 강제 프레임워크 적용**  
    → 테스트 없이 코드 작성하면 삭제하고 다시 시작
- **(04:50)**  
    Superpowers vs 다른 프레임워크
    - Superpowers: 개발 “프로세스” 제약
    - GStack: 역할 기반 검증
    - GSD: 컨텍스트 관리 (정확도 유지)
- **(06:02)**  
    Superpowers 장단점
    - 장점: 코드 품질 ↑, 재작업 ↓, 구조화된 개발
    - 단점: 느림, 토큰 사용량 증가 → **빠른 프로토타입에는 부적합**
- **(06:42)**  
    가장 중요한 결론  
    → “도구 많이 아는 것”보다  
    👉 **현재 문제를 해결하는 도구인지가 중요**  
    → FOMO로 도구 쓰면 생산성 오히려 감소

### 🧠 추가 인사이트 (Glasp 기반)

- Superpowers는 단순 플러그인이 아니라  
    **“설계 → 계획 → TDD → 리뷰” 전체 개발 프로세스를 강제하는 프레임워크**이며,  
    AI가 계획 없이 코드를 바로 작성하는 문제를 해결하기 위해 등장
- 특히
    - 테스트 먼저 작성
    - 계획 기반 실행
    - 자동 코드 리뷰  
        같은 구조를 통해  
        👉 **AI 개발의 품질과 일관성을 크게 개선하는 것이 핵심 가치**
