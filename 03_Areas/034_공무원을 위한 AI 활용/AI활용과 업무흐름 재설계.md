출력 추가

```
[출력]
```

이게 중요한 이유는 이후 목차별 프롬프트 생성 시 근거가 됨.

# 2단계 : 목차 생성 프롬프트

출력을 이렇게 바꾸는 것이 좋음.

```
[출력]Level1Level2Level3Level4각 목차별- 작성 목적- 대응 요구사항- 대응 평가항목- 포함해야 할 핵심 내용- 추천 도식
```

예)

```
2.2.3 AI 기반 사전예방 점검체계작성목적- 운영 효율성 강조대응요구사항- 장애 예방- 모니터링 고도화평가항목- 수행전략- 기술성핵심내용- AI 분석- 이상징후 탐지- 자동 알림추천도식- AI 분석 프로세스
```

# 3단계 : 목차별 프롬프트 생성

이 단계가 핵심.

현재 생각한

```
목차명:RFP 요구사항:
```

만으로는 부족함.

최소 아래 정보는 들어가야 함.

```
사업명:상위목차:현재목차:목차 작성 목적:관련 요구사항:관련 평가항목:제안 전략:차별화 전략:전후 목차 관계:
```

---

예시

```
사업명:통합연계 고도화 사업상위목차:2. 추진전략현재목차:2.2.3 AI 기반 사전예방 점검체계목차 작성 목적:운영 고도화 전략 설명관련 요구사항:- 장애 예방- 자동 점검관련 평가항목:- 수행전략- 기술성제안 전략:- AI 적용- 자동화차별화 전략:- Rule 기반이 아닌 ML 기반 예측전후 목차 관계:2.2.2 모니터링 체계↓2.2.3 AI 점검체계↓2.2.4 운영체계
```

# 4단계 : 페이지 생성 프롬프트

여기서도 지금 생각한 출력보다 하나 더 필요합니다.

```
[출력]1. 페이지 핵심 메시지(3줄)2. 본 페이지의 역할3. 포함해야 할 핵심 내용4. 차별화 포인트5. 슬라이드 구성안6. 추천 도식7. 상세 작성 내용
```

특히 **"슬라이드 구성안"** 이 중요합니다.

예)

```
상단- 핵심 메시지좌측- 현행 문제점우측- 개선방안하단- 기대효과
```

또는

```
상단- 추진전략중단- 4대 전략하단- 기대효과
```

이렇게 나오면 실제 PPT 작성 자동화까지 연결 가능합니다.

---

제안 업무 관점에서는 최종적으로 아래 구조가 가장 실무적입니다.

```
RFP↓요구사항 분석↓목차 생성↓목차별 메타정보 생성(목적/평가항목/전략/도식)↓목차별 프롬프트 생성↓슬라이드 작성
```

특히 "목차별 메타정보 생성" 단계를 추가하면 이후 100페이지짜리 제안서도 목차 단위로 일관성 있게 생성할 수 있습니다. 이것이 제안PM들이 사용하는 문서 설계 방식에 가장 가깝습니다.
