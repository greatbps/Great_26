# 🧠 2. 기술적으로 반드시 들어갈 요소 (숨은 요구사항)

## 1) 프론트엔드

- IE → Chrome/Edge 기반
- 예상:
    - React / Vue 기반 SPA
    - WebSocket 실시간 상황판
- 군 특성상:
    - **ActiveX 제거 대응**
    - **보안 브라우저 환경 대응**

👉 포인트:

> “단순 화면이 아니라 **상황도 + 실시간 전술 UI**”

---

## 2) 백엔드

- 기존: Monolithic + 레거시
- 향후:
    - **MSA 또는 Hybrid 구조**
    - API Gateway 필요

👉 핵심:

- 40개 체계 연동 →  
    👉 **ESB 또는 API 통합 계층 필수**

---

## 3) 데이터 구조

- 단순 DB 아님
- 특징:
    - 실시간 데이터
    - 이벤트 기반
    - 메시지 큐 가능성 높음

👉 예상 기술:

- Kafka / RabbitMQ 계열
- In-memory DB (Redis 등)

---

## 4) 보안 (이게 핵심 평가 포인트)

이미 힌트 있음:

> 서버보안, SSO, DB 암호화, 자료교환

👉 실제 요구사항 확장하면:

- 국방망 / 폐쇄망 대응
- 다중 인증 (SSO + 인증서)
- DB 암호화 (TDE or 컬럼암호화)
- 망연계 (자료교환)
- 감사로그 / 추적

👉 결론:

> ❗ “보안 아키텍처 설계 능력”이 승부

# 🔗 3. “40여 개 체계 연동”의 진짜 난이도

이게 핵심 난이도다.

## 표면:

- 단순 인터페이스 연동

## 실제:

- 각 체계:
    - 데이터 포맷 다름
    - 프로토콜 다름
    - 실시간성 다름

👉 발생 문제:

- 데이터 정합성
- 지연
- 장애 전파

---

## 반드시 필요한 구조

👉 추천 아키텍처:

[각 체계]  
   ↓  
[Adapter Layer]  
   ↓  
[Message Broker / ESB]  
   ↓  
[통합 데이터 모델]  
   ↓  
[AFCCS]

👉 키워드:

- Adapter 표준화
- Canonical Data Model
- 비동기 처리
