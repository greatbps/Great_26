## 📄 Content
### 🔑 핵심 요약 (타임스탬프 포함)

- **(00:00–00:52)**  
    기존 “바이브 코딩” 방식(대충 요구 → AI 코드 생성 → 오류 수정 반복)은 실패 확률이 높음 → **기획·설계 없는 개발의 한계** 강조
- **(00:52–01:38)**  
    해결책으로 **SpecKit + Claude Code**를 활용한 **명세 기반 개발(Spec-driven development)** 소개  
    → 슬래시 명령어로 단계별 개발 프로세스 실행 가능
- **(01:38–02:20)**  
    바이브 코딩 실패 원인:
    - 요구사항이 불명확
    - 반복 수정으로 코드 붕괴
    - 기능 충돌 및 오류 증가 → 결국 포기
- **(02:20–03:53)**  
    실제 개발에 필요한 요소:
    - 기능 정의서 (로그인, 업로드 등 세부 기능)
    - 데이터베이스 설계 (스키마, 데이터 구조)  
        → AI에 한 번에 맡기면 **원치 않는 구조 생성 위험**
- **(03:53–05:26)**  
    SpecKit 기반 **7단계 개발 프로세스**:
    1. 프로젝트 원칙 설정
    2. 명세 작성
    3. 명확화(Clarify)
    4. 계획 수립 (기술 스택/아키텍처)
    5. 작업(Task) 분해
    6. 구현
    7. 검증
- **(06:12–08:06)**  
    실습: AI 블로그 생성기 프로젝트 초기화  
    → SpecKit 설치 후 Claude Code와 연동  
    → 명령어 기반 개발 환경 구성
- **(08:06–10:23)**  
    프로젝트 원칙 정의:
    - 코드 품질
    - 테스트 커버리지 (≥70%)
    - 성능 & UX  
        → 개발 기준을 먼저 고정
- **(10:23–12:45)**  
    명세 작성 → 기능 구체화 (질문 기반 입력)  
    → 이후 Clarify 단계에서
    - 보안 (XSS, SQL Injection)
    - 재시도 정책
    - 사용 제한 등  
        **누락된 요구사항 자동 보완**
- **(15:18–17:49)**  
    Plan 단계:
    - 기술 스택 자동 결정 (Next.js, TypeScript 등)
    - 데이터 모델, API, 아키텍처까지 생성  
        → AI 선택 이유(리서치)까지 설명 제공
- **(18:31–21:19)**  
    Task 단계:
    - 63개 작업으로 세분화
    - 이후 모델 변경 시 Plan/Task 자동 업데이트  
        → **전체 시스템 일관성 유지**
- **(21:19–24:46)**  
    구현 및 실행:
    - AI가 전체 코드 생성
    - API 키 설정 후 정상 동작
    - 기능: 블로그 자동 생성, 복사 기능 등
- **(24:46–26:18)**  
    검증 단계:
    - 명세 대비 구현 100% 일치 확인  
        → **체계적 접근 시 오류 없이 완성도 높은 결과 가능**
